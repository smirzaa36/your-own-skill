# Three sample inputs and skill runs

All people, organizations, roles, and details below are fictional. The review excerpts show the skill's core behavior on varied inputs.

## Input 1: Software engineering intern

**Job post:** Acorn Labs seeks a software engineering intern to build Python services, write tests, and work with REST APIs. Applicants should explain one project and their contribution.

**Resume:** Mira Patel — Computer Science student. Skills: Python, Java. Project: “Campus Events,” a web app built with two classmates. Added an event listing page. Coursework: Data Structures.

**Skill review:**

**Verdict:** You have a relevant starting point, but this resume gives little evidence for the service and testing work Acorn Labs calls out.

**Strongest match:** The Campus Events app gives you a project to connect to software delivery; the resume says you built its event listing page.

**Priority gaps:**

1. **Tests:** The post asks for test writing; the resume shows no testing. If you wrote tests, name the test type and what they checked. If not, build and document a small test for the project before claiming the skill.
2. **REST APIs:** The post names REST APIs; none appear in the resume. Add an API example only if you actually built or used one.
3. **Your contribution:** “Built with two classmates” obscures ownership. Replace it with the work you personally did. For example: “Implemented the event listing page in [framework]” only if that is accurate.

**First three edits:** clarify personal contribution; add verified test evidence; add REST API experience only if true.

## Input 2: Data analyst intern

**Job post:** Northstar Foods seeks a data analyst intern to clean spreadsheet data, write SQL queries, build clear charts, and explain findings to non-technical teammates.

**Resume:** Dev Rao — Statistics student. Skills: Excel, SQL, Tableau. Project: “Sales Dashboard,” made charts from a class dataset. Volunteer: helped organize a campus fundraiser.

**Skill review:**

**Verdict:** Your listed tools line up well, but the resume does not yet show what you did with them or what someone learned from your analysis.

**Strongest match:** SQL and Tableau are named in your skills, matching tools in the post.

**Priority gaps:**

1. **Data cleaning:** Cleaning is central to the role and absent from the project description. Add the actual cleaning steps if you performed them.
2. **SQL evidence:** SQL is only in the skills list. Add a query task and what it answered, if you can substantiate that from the project.
3. **Communication:** The job asks for findings explained to non-technical teammates. The resume has no example. If you presented the dashboard, state to whom and what decision or insight it supported.

**First three edits:** expand the dashboard project with verified methods; connect SQL to a concrete question; add a real audience or finding if available.

## Input 3: UX design intern

**Job post:** Fieldnote Studio seeks a UX design intern to interview users, sketch flows, prototype in Figma, and explain design choices. A portfolio link is requested.

**Resume:** Asha Menon — Design student. Skills: Figma, Illustrator. Project: redesigned a library booking screen for a class assignment. Activities: poster committee.

**Skill review:**

**Verdict:** The class redesign is relevant, but the resume does not show the user research or reasoning Fieldnote wants to see.

**Strongest match:** The library booking screen is a directly relevant interface redesign, and Figma is listed.

**Priority gaps:**

1. **User interviews:** The post explicitly asks for interviews; none are mentioned. Say whether you interviewed users. If you did, include the number and a finding; if not, do not imply research happened.
2. **Design rationale:** “Redesigned” gives no reason for the choices. Name one actual problem and the change you made to address it.
3. **Portfolio:** The employer requests a portfolio link, but the resume has none. Add a working portfolio URL before applying.

**First three edits:** add the portfolio link; explain one verified design decision; include interview evidence only if you have it.
