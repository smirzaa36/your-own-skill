# Same task, with and without the skill

**Task used both times:** Review the fictional Mira Patel resume and Acorn Labs job post in Input 1 of `examples.md`. Identify how well the resume fits and what to change. The resume and job post were held constant.

## Without the skill

Mira's Python and Computer Science background are relevant. The resume would be stronger with more detail about the Campus Events project. Add the technologies used, explain your role, and mention any testing or API work. Use measurable results if you have them. Tailor the resume to the internship.

## With `/resume-roast`

**Verdict:** You have a relevant starting point, but this resume gives little evidence for the service and testing work Acorn Labs calls out.

**Strongest match:** The Campus Events app gives you a project to connect to software delivery; the resume says you built its event listing page.

**Priority gaps:**

1. **Tests:** The post asks for test writing; the resume shows no testing. If you wrote tests, name the test type and what they checked. If not, build and document a small test for the project before claiming the skill.
2. **REST APIs:** The post names REST APIs; none appear in the resume. Add an API example only if you actually built or used one.
3. **Your contribution:** “Built with two classmates” obscures ownership. Replace it with the work you personally did. For example: “Implemented the event listing page in [framework]” only if that is accurate.

**First three edits:** clarify personal contribution; add verified test evidence; add REST API experience only if true.

## What improved

The no-skill answer gives broad advice and groups tests and API experience together as possible additions. The skill version ties each issue to a stated job requirement, cites exactly what the resume does or does not say, separates verified facts from missing evidence, and gives a concrete edit order. It also avoids inventing a metric or claiming experience the sample does not establish.
